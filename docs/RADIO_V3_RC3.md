# Radio 1.1.0-rc3

2026-10-30。针对 COM6 上的大字编辑风、点阵电波和换台等待问题修订。此次仅抓取原固件截图和串口日志，未复位或烧录设备；新固件仍待真机验收。

## 真机观察

点阵电波截图显示杭州华语之声网络广播，状态为连接失败。台名没有频率信息，旧界面显示 `----`，形成一条横线，音频图形也被画成实心短条。大字编辑风的相同台名因超过八字被降至小字号，破坏了主视觉，右侧的 Internet radio 又折成小字。

监听期间记录到 `no data for 15000ms`、`stream stop`、重连、证书验证，再到 `playing: 48000 Hz ch=2 MP3`。因此确有断流和重连；本次没有捕获持续无限 buffering 的完整过程，不能把源码缺陷当成已经由真机日志证明的唯一原因。电脑端读取两条杭州公开 MP3 流均返回 HTTP 200，其中当前电台一次取首批 2KB 约需 7.8 秒，另一台约 1.7 秒；这不是设备端网络性能测量。

## 布局修订

- 大字编辑风使用 64 / 48 / 40px 标题，按台名长度分行。超过可用行数时截断，完整名称仍可在电台列表查看。
- 增加 350 字的 48px 标题子集，来自现有 Noto Sans SC 源文件；保留 SIL OFL 声明。其余字回退至已有网络字库。生成脚本为 `tools/prepare_radio_title_font.py`，需要 Pillow。
- 大字缓存最多 32 个字形，占用 128KB PSRAM；不修改 LVGL 绘制缓冲或屏幕驱动。
- 点阵数字使用圆点，小数点采用窄字宽；无 FM 频率的台显示 `NET`，不伪造频率。
- 点状音频波形读取现有 PCM 电平。暂停、连接和失败时显示静止基线，不用假动画冒充音频。
- 十套风格与现有手势保留：主屏左右滑换风格，上一台/下一台按钮换台，顶部下滑打开控制中心。其余操作见 [RADIO_OPERATIONS.md](RADIO_OPERATIONS.md)。

## 播放器修订

- 释放网络任务每次分配的 4096 字节读缓冲，避免随换台、重连累积泄漏。
- HTTP 连接完成后才进入 BUFFERING 并启动首帧计时。单次连接等待约 20 秒时请求退出；累计启动等待达到 30 秒时不再开始下一次网络重试。阻塞的 HTTP 调用及清理仍需等待其自身超时，不能把 30 秒视为严格的端到端上限。
- URL、codec、命令代际在同一临界区取快照；旧会话不能覆盖新请求的状态，已处理代际不会因残留唤醒信号被重复播放。
- 退避等待每 50ms 检查是否已换台；重定向过程也检查取消。
- 首帧前暂停恢复不会提前显示 PLAYING。未知 codec 可进行 MP3/AAC 改判。重试清零按已成功输出的 PCM 音频时长计算，短暂出声后的空等或暂停不会冒充十秒有效播放。
- 解码无输入消耗时退出当前内层循环，音频输出启动或写入失败时结束会话；验证解码器输入消耗和输出长度。采样率和声道使用会话局部值，避免换台时公共参数清零影响尚在退出的旧帧。
- 网络空闲使用实际 tick 时间，避免把每次 EAGAIN 都当成等待了完整超时。
- 播放请求提交失败时停止旧流、显示失败，播放按钮重试当前台，避免还显示旧台的 LIVE 状态。

## 验证及边界

开发环境检查通过。`idf.py build` 实编译通过，应用镜像 2,968,480 字节（0x2d4ba0），适配当前 3MiB 应用分区；`pack_app.py` 通过不带地址应用包校验。镜像已占平台 2.9MiB 提交上限约 98%，后续增加素材前需控制体积。

`tools/test_radio_host.py` 使用真实 LVGL、界面、控制器、页面和设置代码，运行 120 次界面重建，输出 32 帧；检查十套切换、分页、保存失败、播放提交失败、暂停及覆盖层操作。

同一脚本另外编译真实 `main/radio_player.c`，使用确定性的任务调度、HTTP、解码器和音频替身，覆盖 100 次会话缓冲释放、8 秒连接、旧请求取消、首帧前暂停恢复、无消耗解码、音频启动失败、坏流退出、UNKNOWN 改判和重复唤醒。它验证应用控制流，不代表真实 FreeRTOS 并发、MP3/AAC 解码、I2S 输出或 Wi-Fi 已通过验收。

中文子集检查、圆屏文本宽度检查均通过。没有修改平台引导层、分区表、屏幕驱动或 I2S 时序。
