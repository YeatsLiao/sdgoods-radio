# 谷仓次元屏 · 桌面网络电台技术方案

> ⚠️ 免责声明：本方案为设计草案，所有组件/API 的具体用法与参数需按项目实际调整；
> 端口、域名、分区等既定参数以平台现状为准，未经确认不得改动。

## 1. 项目定位

一台放在桌上的圆屏网络收音机：开机即连 WiFi（复用已做好的配网），
从 Radio Browser 拉取城市热播电台列表，触摸换台，圆屏显示 FM 刻度表盘风格的电台 UI。

关键认知：设备收的是**网络流**（WiFi 拉取互联网电台服务器的 MP3/AAC 流），
不是电磁波；"FM 频率"仅为 UI 装饰（从电台名解析显示，设备无收音硬件）。

## 2. 参考项目与借鉴边界（不照搬，分层处理）

基调是「参考 → 重构 → 超越」，**不是「移植」**。leo-radio 的价值是"这条路走得通"，不是"代码拿来用"。明确三层边界：

| 层 | 内容 | 处理方式 |
|---|---|---|
| **直接用（官方组件）** | esp_audio_codec（MP3/AAC 解码）、esp_codec_dev、LVGL、HTTP 客户端 | 本就是乐鑫官方库，按我们工程集成，无"抄"的概念 |
| **参考思路（看它怎么组织，不搬代码）** | 播放器链路组织方式（拉流→解码→输出）、Radio Browser 目录请求逻辑、配网与播放的状态关系 | 理解后按谷仓架构**重写**，接口、数据结构、文件划分都按我们自己的来 |
| **必须重构** | 全部 UI、交互、状态机、设置页、圆屏适配、目录缓存策略 | 按谷仓 360×360 圆屏 + 触摸 + 平台音频层重写，不复制其代码 |

参考信息：leo-radio（MIT，ESP-IDF 5.5，ESP32-C3），播放链路 esp_audio_codec + esp_codec_dev + HTTP 拉流，电台目录走 Radio Browser API。克隆后只作**阅读理解**（放在工程之外，不进 sdgoods-radio 仓库），重点看链路可行性和它踩过的坑，不直接合并代码。**红线：sdgoods-radio 工程不得包含任何 leo-radio 代码 / 组件**（尤其其 esp-wifi-connect、ES8311 外挂 codec 那套）。

## 3. 内容源：Radio Browser API

- 社区维护的全球电台目录（类维基），数据 public domain，开放 API 免费使用
- 提供：电台名、流地址、标签、语言、国家/州、点击量（可做热播排序）
- 主要接口方向（以官方文档为准）：
  - 按国家/城市/标签搜索电台列表
  - 按点击量取热播电台
  - 直接拿流 URL 播放
- 入口：`https://api.radio-browser.info/`（有多地镜像，实测选最快的）

## 4. 谷仓次元屏适配清单

| 差异项 | leo-radio | 谷仓次元屏 | 对策 |
|---|---|---|---|
| 芯片 | ESP32-C3 | ESP32-S3（+PSRAM） | 直接适配，资源更宽裕 |
| 屏幕 | 小方屏 | 360×360 圆屏（安全区 x,y∈[60,300)） | UI 重画，FM 刻度表盘天然适配圆屏 |
| 交互 | 物理按键（ADC 3 键） | 全触摸 | 触摸点台 / 滑动切台 / 长按收藏 / 上滑返回（平台手势） |
| 音频输出 | 自建 I2S + ES8311 外挂 codec，`set_format` 动态改采样率 | 平台 I2S0（static 句柄）**固定 16kHz/16bit/stereo 直推功放**；现有 `sdgoods_audio_play_pcm()` 一次性阻塞播完即关功放 | **平台层新增流式播放 API**（`stream_start/stream_write/stream_stop`，以"新增"方式提供）：`stream_start` 按需重配 I2S0 时钟到流采样率（或应用层重采样 16k 兜底）；解码 PCM → `stream_write` → I2S0 → 功放 → 喇叭 |
| 配网 | esp-wifi-connect（自建全键盘） | 已有 wifi_prov（SoftAP + 192.168.4.1 网页配网 + NVS + STA 状态机） | **复用现有 wifi_prov，不用 leo-radio 的 esp-wifi-connect**；电台应用内显示网络状态 |
| 平台约束 | 无 | 独立应用工程（不上架 AI Passport） | 平台组件已随工程派生一份自维护；扩展 API 以"新增"方式提供，不改既有 record/play/bgm 行为契约 |

## 5. 目标架构（模块划分）

### 5.0 UI 设计目标（做出超越参考的水平）

UI 是我们的差异点，参考项目只是"能播"，我们要做"好看且好用"。设计原则：

| 维度 | 目标 | 说明 |
|---|---|---|
| 圆屏原生设计 | FM 刻度表盘为视觉核心，指针扫动动画 | 360×360 圆的天然主场，参考项目是方屏，刻度是平铺的；我们做环形刻度 + 换台时指针沿弧扫动（动画流畅、有反馈） |
| 视觉风格 | 深色主题、克制配色、夜间友好 | 桌面摆件长时间亮屏，低亮度深色不刺眼；信息分层清楚（正在播的台最醒目） |
| 交互设计 | 全触摸手势体系 | 点台/换台、上滑返回（平台手势）、长按收藏、左右滑切台；控件都在安全区内且不小 |
| 播放反馈 | 状态清晰 + 氛围细节 | 播放中显示台名/频点/缓冲状态；可选：播放时表盘指针微动、频谱/声波动效、断网重连状态明确 |
| 设置体验 | 音量、亮度、定时播放、收藏 | 环形/滑杆交互适配圆屏，不堆砌菜单 |
| 中文界面 | 全中文，字体子集化 | 复用萌宠项目的字体工具链 |

验收标准：第一屏（播放态）3 秒内能看懂在放什么台、怎么换台；不依赖说明书。

```
仓库根（独立派生工程，基座携带 wifi_prov）
├── main/
│   ├── apps/ui_radio.c/.h     # 电台应用：圆屏 FM 表盘 UI + 触摸手势状态机（选台/播放/暂停/音量）
│   ├── radio_player.c/.h      # 播放器：HTTP 拉流 → esp_audio_codec 解码（MP3/AAC）→ 调平台流式 API 输出
│   ├── radio_catalog.c/.h     # 电台目录：Radio Browser API 客户端 + 定位 + 内置兜底列表
│   ├── radio_settings.c/.h    # 设置：音量、亮度、定时播放、收藏（走 sdgoods_appdata / NVS）
│   └── wifi_prov.c/.h         # 复用现有配网模块（不改）
├── components/                # 平台层扩展（新增 API，不改既有）
│   └── sdgoods_board          # 新增 sdgoods_audio_stream_start/write/stop：解码 PCM → I2S0 输出
└── tools/                     # 电台列表打包脚本（可选）
```

数据流：

```
Radio Browser API ──(WiFi)──> 电台列表 JSON ──> catalog 缓存
电台服务器 ──(HTTP 流, MP3/AAC)──> player 拉流 ──> esp_audio_codec 解码 ──> PCM ──> 平台 I2S0 ──> 功放 ──> 喇叭
```

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Radio Browser 服务器在海外，国内访问慢/不稳 | 列表加载慢 | 内置常用城市电台列表兜底 + API 刷新；实测选最快镜像 |
| 电台流为第三方维护，可能失效/变地址 | 播放中断 | 播放失败自动跳下一台；目录定期刷新 |
| 流格式混有 MP3/AAC/OGG | 部分流播不了 | esp_audio_codec 均支持；选台优先 MP3/AAC |
| 流地址为 HTTPS，证书校验 | 拉流失败 | 按需配置 mbedtls 信任或按平台现状处理（以实测为准） |
| 平台 I2S0 已被占用 | 应用层无法自建 I2S | 走平台新增扩展 API（不新开 I2S 控制器） |
| 断网 | 无法播放 | UI 显示断网状态；WiFi 自动重连（复用配网状态机） |
| （高）基座无配网 | 开机无网可配，一切依赖联网 | 从携带 `wifi_prov.c` 的工程派生，或显式并入 wifi_prov（不用 leo-radio 的 esp-wifi-connect） |
| （中）采样率落地 | I2S0 固定 16k，流常 44.1/48k | 流式 API 内重配 TX 时钟（首选）；若不动时钟则应用层重采样到 16k（兜底，音质略降） |

## 8. 已确认事实（供实现参考）

- 设备 flash 32MB；appdata = 16MB FAT（@0x1000000）；app 分区 3MB（当前固件约 1.63MB，余 46%）
- 平台音频：I2S0（TX，16bit stereo）→ 功放 → 喇叭，I2S1（RX）→ 麦克风；
  `sdgoods_audio_*` 提供 BGM/音效/音量/录音回放；**已有 `sdgoods_audio_play_pcm()`，但它是一次性阻塞播完即关功放的 16kHz 单声道接口，不适合连续电台流**（需新增 `stream_start/write/stop` 流式 API）；I2S0 固定 16kHz，与电台流 44.1/48k 存在采样率缺口（见 §4 对策）
- 配网：`wifi_prov.c`（SoftAP `SDGOODS-*` + 192.168.4.1 网页配网 + NVS 存储 + STA 状态机），已烧录验证；**注意裸基座 SDGOODS-ESP32S3 的 `sdgoods_wifi.c` 只有 init+scan，无配网状态机——必须从携带 wifi_prov 的工程派生**
- 屏幕：360×360 圆屏，LVGL 8.3，GIF/触摸链路已通（萌宠项目验证）
- 真机验证方式：烧录 + `screenshot_recv.py` 截图（串口日志在 UART0，不可读）
