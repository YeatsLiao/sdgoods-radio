# 圆屏电台 v3：十套可切换风格的固件实施计划

计划制定日期：2026-10-29。更新：2026-10-30，十套静态皮肤已接入 1.1.0-rc1 候选固件并通过构建和离线检查；用户设备不在现场，真机条目待远端验收。实际交付与未完成项见 [RC1 记录](RADIO_V3_RC1.md)。以下保留原分阶段安排与制定计划时的环境快照。

设计依据：[十套风格档案](design/radio-v3/README.md) 与 [机器可读清单](design/radio-v3/skins.json)。这些是已确认方向，后续实施应以本计划为准，旧 `UI_REDESIGN.md` 用作历史参考，不把其中旧手势与布局直接当作新需求。

## 1. 目标与范围

在现有 ESP32-S3 / LVGL 8.3 电台中实现十套可切换皮肤。播放器、目录、收藏、配网和控制中心共用；换皮肤只改变显示，不换台、不停播、不重新连接网络。

保留全部十套，但分批验证：先 S02 点阵电波与 S05 猫咪 DJ，证明同一播放器能在图形皮肤与像素皮肤间稳定切换，再补齐其余八套。默认开机皮肤建议暂用 S02，最终默认值待真机效果确认；用户没有指定猫咪为出厂默认。

第一版交付十套静态皮肤、完整动态文字与状态、外观选择页、跨重启记忆、基本换台与暂停交互。角色动画、场景动画和陪伴时钟作为后续增量，不让动画阻塞十套静态皮肤的交付。

### 容量边界

实际 `platform/partitions.csv` 中应用槽为 **0x300000 = 3,145,728 字节（3MiB）**，不能沿用旧文档里「单应用可用 31MB」的假设，也不能修改平台分区表来腾空间。

现有 `build/SDGOODS_RADIO.bin` 文件为 **2,648,960 字节**，按 3MiB 粗算剩 **496,768 字节（约 485KiB）**。这是 2026-10-27 的旧产物，只是规划参考；实际余量以第一次基线构建与打包检查为准。

一张 360×360 RGB565 图未经压缩为 259,200 字节，十张约 2.47MiB；若 PNG 解码使用四字节像素，单张输出约 506KiB。故不能承诺把十张全屏无压缩图直接内嵌进当前固件。

## 3. 资源生产与容量策略

采用「共享动态 UI + 每套独立美术资产」，不将整张效果图当成运行界面。

1. 每款准备独立的无文字角色／场景图片；主色、文字、按钮、点阵和波形由程序绘制。示例图中的台名、频率、时钟不能被烘焙进最终素材。
2. 大字、点阵和声波三款尽量不用大位图；像素款只保存需要的角色或上部场景，纯色区域由 LVGL 填充。共用图标、字号和按键反馈。
3. 先为 S05 生成目标尺寸像素角色与小缩略图，比较索引图、RGB565、PNG 等实际体积、透明度、显示质量与解码峰值。选择项目现有 LVGL 能支持且真机验证通过的格式，不预先假定某格式必然更省。
4. 以最终基线余量制定十套素材总预算；建议保留不少于应用槽 5% 的工程余量作为规划目标。若基线达不到，先列出体积贡献与资源优化方案，不挪平台分区或擅自删除现有能力。
5. 优先让十套静态皮肤随应用自包含分发，避免初次使用依赖下载。仅在实测无法容纳时，评估应用私有 appdata 资源包；先核实官方分发、安装、校验、版本匹配与离线兜底，完整实现资源安装链路后再采用。不能只把素材放到开发板文件系统就宣称平台用户也能安装。
6. 若采用外部资源，始终内置 S02 等轻量兜底皮肤；缺图、校验失败或 appdata 不可用时清晰回退，不黑屏。主题目录不读取或覆盖别的应用数据。

所有图片保留来源记录；当前两张对比图继续按原文件保存。拆分、重生成与修订资产用新版本文件；像素图在真实 360×360 比例下检查边缘，不靠模糊插值掩盖细节问题。

## 4. 皮肤接口与状态归属

以下是**拟新增**文件，不表示已经存在：

- `main/apps/ui_radio_skin.h/.c`：十套稳定 ID 的登记表、配色、布局类型、素材描述、默认及回退皮肤。
- `main/apps/ui_radio_assets.h/.c`：素材描述与加载／释放入口；根据实际格式再决定是否需要转换工具。
- `main/assets/radio/`：运行时素材及轻量缩略图；仅保存最终可用资产，不把宣传拼图编入固件。
- 后续若新增转换脚本，放在 `tools/`，生成文件、缓存与可重现命令另行记录。

每套皮肤描述包含：稳定 ID、中英文名称、颜色、布局类型、资源引用、文字区域、按键区域、可选动画描述。布局可分为文字型、频率型、角色／场景型，不强迫十款共用一套僵硬坐标；操作语义保持一致。

UI 只读取同一份电台、播放状态、用户暂停意图、音量、定时信息。切换皮肤不能调用电台退出／停播路径或重新启动目录任务。页面回调按语义键关联，不按显示名称分支。

皮肤切换流程：读取目标描述 → 检查素材可用 → 准备必要资源 → LVGL 线程更新界面并重绑外壳 → 成功后持久化 ID → 释放旧资源。失败时保留原界面或回退 S02，不提前写入不可用 ID。重用对象优先；若要重建屏幕，取消旧定时器、关闭旧浮层、解除旧指针，并检查新旧资源同时存在的瞬时峰值。

文件读取／图片预处理等耗时操作进入后台任务，后台只交付数据和完成标记；所有 LVGL 对象、事件与定时器操作回到 UI 主循环。`*_poll()` 不阻塞。

### 设置迁移

- 新增稳定字符串键（拟为 `skin_id`），不把十套硬塞进旧 `night` bool。
- 旧配置迁移建议：已有 `skin_id` 则优先使用；没有时，旧夜色映射 S02、纸张映射 S01；完全无历史则暂用推荐默认 S02。迁移失败不清空 Wi-Fi、城市、定时和收藏。
- 未识别的 ID 回退有效默认值；用户切换成功后再保存，重启后恢复。
- 收藏目前按目录下标存位图，目录刷新会有错位风险。可作为独立可靠性工作项改为稳定电台标识；不要混进每套皮肤。此次切肤至少保证不修改收藏内容。

## 5. 产品交互与布局基线

- 主屏明确提供上一台、播放／暂停、下一台与选台入口；不以点击空白来切换播放状态。所有点按走平台位移守卫。
- 水平轻扫一次切相邻一台作为第一版方案，不引入连续跨多台拖拽；先审计现有事件所有权，避免与平台手势竞争。
- 顶部下滑继续使用平台控制中心，底部上滑及设备退出行为遵循 `sdgoods_app_shell` 的 SINGLE/MULTI 语义；不能继续用底部上滑开列表覆盖系统行为。
- 设置通过可见入口访问；「设置 → 外观」进入轻量缩略图选择页。预览是临时选择，点击「应用」才切换与保存；返回取消。未安装资源不得显示为已经可用。
- 所有非全屏控件和文字优先收在 `SDG_UI_SAFE_*` 的 240×240 安全矩形。顶边手势区不放应用按钮；背景和场景装饰可以延伸到圆边。
- 播放键有效触控范围暂以约 48px 为起点，中央主键可以更大；受实际安全区约束，以真机可点性为准。列表键采用明确入口，不照搬拼图里靠外侧的小图标。
- 有真实频率显示 FM；无频率时显示网络电台／城市等有效信息，避免放大随机频道号或编造频率。
- 长台名最多两行，字号按预设档位降级；极长文本采用可识别的省略策略并在列表查看全名，不默认持续跑马灯。英文名称同样验证。
- 明确区分连接、缓冲、播放、暂停、错误、离线和无台状态；错误不画成正常 LIVE。手动暂停在换皮肤、恢复网络和重建屏幕后依然有效。
- 两套频谱视觉使用实际电平；暂停后停止更新。先检查当前自动失败跳台策略，连接失败保留台名并提供重试／下一台，不在用户不知情时无限跳台。
- 所有新增固定文案用 `SDG_T("中文", "English")`，网络台名走现有网络字体和缺字处理；品牌与官网继续使用已有宏。

## 6. 实施顺序与完成条件

### P0：建立可回归基线

- 重新激活环境并运行检查脚本；记录 SDK、工具链、构建目录。
- 原地 `idf.py build`，确认工作目录与 `CMAKE_HOME_DIRECTORY` 一致；若另有编辑／构建分离再向用户确认路径。保留 `binary size` 和 `Project build complete`。
- 记录固件大小、app 槽余量、启动后的内部 SRAM/PSRAM 空闲量与最大连续块、播放时音频稳定性，以及当前主屏／设置页截图。
- 验收：基线真正编译成功，能够重复播放；否则先修复阻碍，不继续皮肤功能。

### P1：生产规格与首款素材

- 将十套参考图归纳为三种布局，在 360×360 下确定安全区、文字、按键和图像区域。
- 为 S05 制作无文字角色图、所需透明度与缩略图；必要时使用生图迭代，不直接提取带文字截图作底图。
- 实测资源格式与容量，明确十套可自包含分发的预算；不达标则先完成资源分发方案评估。
- 验收：S05 单款目标尺寸预览清楚，控件不越界，容量有测量依据。

### P2：双皮肤最小闭环

- 接入登记表、皮肤设置迁移与外观选择页；实现 S02 与 S05 的动态界面。
- 整理主屏事件所有权、可见选台入口和状态反馈；保持播放器独立。
- 验证播放中切换、暂停中切换、无频率台、长台名、配置保存与重启恢复。
- 验收：两款可反复切换，播放任务不因切肤重启，无卡死和资源持续增长；真实编译及真机截图通过。

### P3：补齐十套静态皮肤

- 接入 S01、S03、S04、S06、S07、S08、S09、S10 的布局与最终资产。
- 逐款验证状态、中英文、字体与对比度；所有缩略图有正确 ID 和名称。
- 验收：选择页完整提供十套，每套都能应用并在重启后恢复，打包体积合规。资源尚未交付时不得用重复图片占位宣称十套完成。

### P4：像素动画与陪伴体验

- 为猫咪／像素主播等优先提供少量眨眼、听歌、暂停帧；按需要再加入雨滴、海浪、植物等局部动画。
- 建议从 4–8fps 局部更新起测，不做十套全屏 GIF 常驻；播放声音优先。控制中心打开、页面离开、静态暂停时按场景停掉装饰动画。
- 陪伴时钟、定时停止播放与熄屏行为单独实施，避免混淆停播、熄屏和关机。
- 验收：局部动画无明显音频中断，离开页面后计时器与资源释放；低内存时可退回静态皮肤。

### P5：回归、截图与交付

- 每个代码阶段运行 `idf.py build`；新增 `.c/.h/.py` 后运行许可头脚本，并检查改动范围。
- 新中文重跑字体生成和 `--check`；新字号、长文案、坐标变动更新度量条目，再运行 `font_metrics.py`。
- 十套各至少保留一张主屏真机图；另检查外观、列表、设置、控制中心和关键错误／暂停状态。
- 在 S02、S05、S08 等代表皮肤下覆盖长台名、网络台无频率、断网重连、用户暂停、定时、连切电台。切肤至少循环 100 次，记录资源是否出现持续下降；连续播放建议至少 30 分钟，最终时间按现场验证能力记录。
- 测量冷启动、切肤与换台响应；切肤即时给出选择反馈，目标不引起可感知音频中断。网络出声时延单独记录，不把公网表现当作固定 1 秒承诺。
- 动画启用前后比较内部 SRAM、PSRAM、最大空闲块和音频表现；记录瞬时峰值，不只报启动空闲量。
- 烧录前重新探测串口，使用官方 `platform/prebuilt/` 引导层与仓库本地烧录工具；不固定 COM 号、不修改平台分区。
- 检查现有及新增临时串口探针；仅在开发构建内验证，交付时去掉临时导航与诊断分支，不将测试入口当正式能力。
- `tools/pack_app.py` 校验不带地址的纯应用包；编译、真机截图、内存记录与最终包共同交付。上传平台另按用户后续发布指令执行。
